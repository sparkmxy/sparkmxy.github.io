# 周易 · 蓍草占筮

以朱熹《筮仪》为依据的中文静态占筮网页。使用原生 HTML、CSS、JavaScript，无构建步骤或第三方运行依赖，可直接由本仓库的 GitHub Pages 在 `/iching/` 路径提供访问。

## 本地使用

在仓库根目录运行（需要现代版本 Node.js）：

```sh
node iching/serve.mjs
```

浏览器打开 <http://127.0.0.1:4173/iching/>。预览服务仅监听本机，只提供 `iching` 文件夹内容；可通过 `PORT` 环境变量修改端口。浏览器需通过 HTTP 或 HTTPS 访问，不建议直接双击 HTML 文件。

运行验证：

```sh
node --test iching/tests/*.test.mjs
```

导出完整卦记后，可在本机复算：

```sh
node iching/verify.mjs "导出的卦记.json"
```

复核器校验记录版本、算法模型、随机数格式与拒绝采样，并逐项比较六爻十八变和消耗计数。成功退出码为 `0`，不一致为 `1`，文件或 JSON 错误为 `2`。结果只说明记录内部计算一致，不能证明随机来源或记录时间；未使用的随机数也无法由演算结果验证。

填写所问之事、选择随机源后起卦。每爻三变，六爻共十八变，自下而上成卦；结果展示本卦、变爻、之卦与可复核的演算过程。

## 经文与传文

六十四卦均收录卦辞、六爻爻辞、完整《彖传》与《象传》。《象传》区分说明全卦的大象与逐爻对应的小象；乾、坤还收录用九、用六及其对应小象。古文来自各卦所附的维基文库《周易》原文链接，采用简体字形，保留古籍异文。

起卦结果中的本卦和之卦均展示卦辞、彖传与大象；动爻下面附对应小象，展开六爻可通读本卦全部爻辞与小象。卦典也提供完整经传。已收藏的卦记在重读时自动使用这些新增经文。

### 《周易译注》

译注依据用户提供的黄寿祺、张善文《周易译注》（上海古籍出版社，2007 年 4 月第 1 版）上下册 PDF 整理，覆盖全部六十四卦。上册正文书页 1–224 对应第 1–38 卦；下册书页 225–373 对应第 39–64 卦。扫描文字按原书分栏提取，译文与总论另对照扫描图校读。

每段已展示的卦辞、爻辞、彖传、大象、小象及乾坤用辞都有独立的「注释与白话译文」折叠区，初始关闭。原书的译文、注释和说明分项呈现，并标注书页。乾卦小象在原书合段注释，界面明确说明共享范围。每卦「总论」直接显示，不置于折叠区；本卦、之卦、卦典及重读历史卦记使用同一套译注数据。

本次译注覆盖网页现有古文条目，不另增乾坤《文言》等尚未展示的篇章。古文与译注采用各自底本，字形或断句可能有异。上册书页为 `PDF 页码 - 31`，下册书页为 `PDF 页码 + 217`；每处引用标明册次与书页，可对照上传文件核查。完整 PDF 未复制进网站目录。

注释和说明以原书 OCR 为底本，修复了分栏错序、段落边界及已发现的识字问题，未宣称完成全书逐字校勘。下册少数译文的原扫描图严重缺字，依对应经文和书中注释补充的白话释义会在该段内明确标注；不冒充原书逐字译文。

人工修订记录及后续校验方式见 [译注数据维护说明](../scripts/iching-book/README.md)。

## 蓍草算法

依据[《原本周易本义》卷末下·筮仪](https://zh.wikisource.org/zh-hans/原本周易本義_(四庫全書本)/卷末下)：五十策取一不用，每爻从四十九策开始；每变分二、右取一策为挂一、左右各以四计数，余数为一至四，整除时留四。除去挂一与两边余策，三变后以余策除以四，得到六、七、八、九。

程序将左堆的四种余数视为等可能，再从该余数对应的合法分堆中等概率选取分堆；右堆在挂一后仍须有策。这一建模对应原文一变三奇一偶、后两变奇偶各半，老阴、少阳、少阴、老阳的概率分别为 `1/16、5/16、7/16、3/16`。**这不是所有分堆大小等概率的模型，也不声称重现真实手分蓍草的物理概率。** 每一步均保留实际左右策数与去留策数。

## 随机源与记录

- **RANDOM.ORG 公共接口（默认）**：无需 API Key，以大气噪声提供随机数。官方已将此 HTTP 接口列为旧接口；可用性、IP 额度、网络和浏览器跨域策略均可能影响访问。[官方说明](https://www.random.org/clients/http/)
- **Web Crypto**：用户可主动选择浏览器的 `crypto.getRandomValues()`。无需请求外部随机服务；它是浏览器提供的密码学随机源，不宣称为大气噪声或独立物理随机源。

各来源的整数均通过拒绝采样映射到所需范围，避免取模偏差。全站不使用 `Math.random()`，外部服务失败时明确报错，**不会静默切换随机源**。重新起卦会重新获取随机数。

起卦时问事内容在浏览器内处理，不发送给随机服务；随机服务仍会接收到请求者的 IP 等网络信息。点击「AI 解卦」后，浏览器先向 Appwrite 与 Cloudflare 发送不含问题的连通性检查，再将本次提问与六爻数值发送给选中的服务，由它结合经传原文请求 Google Gemini。只有主动开启保存功能后，卦记才写入当前浏览器的本地存储。JSON 导出包含随机源信息、原始随机整数和十八变过程，可用于复算；它不带 RANDOM.ORG 数字签名，不是第三方认证凭证。导出的问事内容请自行保管。

## AI 解卦

六爻生成完成后，「筮 · 蓍草成象」卡片下方出现「AI 解卦」。点击后在卦辞阅读区上方显示解读，支持等待提示、停止等待、失败重试和重新解读。没有填写问题时解读整体卦意；修改提问输入框不会改变已起卦的提问。重读已收藏的卦也可以请求解读。

浏览器只提交本次问题及自下而上的六个数值，两条服务均使用 `ai-prompt.mjs` 核对本卦、之卦、上下卦和动爻，加入相应卦辞、彖传、大象、本卦六爻及小象；乾坤六爻皆动时加入用九、用六。提示词把用户问题作为资料，并要求区分经文与 AI 解释、不编造书中译注。书中现代译注、总论、随机原始数和历史记录不发送给 Gemini。

Gemini API Key 仅保存在 Cloudflare / Appwrite 的 Secret `GEMINI_API_KEY`，浏览器公开配置 `ai-config.mjs` 只存接口地址。Appwrite 的私有检查口令不进入正式前端。解读仅留在当前页面，不写入已收藏卦记或 JSON 导出；切换卦象会清除解读并停止等待旧请求。结果按纯文本显示，不执行模型生成的 HTML。

自动选线在每次点击时执行：两条健康检查并行，单条最多等待 10 秒，为冷启动和较慢的跨境连接留出时间。选择时已收到 Appwrite 的 `CN` 地区提示且正式接口就绪则优先新加坡；已收到其他有效地区提示时优先 Cloudflare，不可达再使用新加坡。缺少地区提示时先通过健康检查的线路即可使用，不继续等待另一条被阻断的线路；两条同时就绪时优先 Cloudflare。VPN 可能改变服务看到的出口地区；此策略不保证严格按访客国别分流，不猜测用户真实位置。旧版 Appwrite 探针和未开启 `PUBLIC_AI_ENABLED` 的接口不会成为正式线路。检查不会调用 Gemini、传递问题或返回完整 IP。

选线完成后只发送一次生成请求。提交后发生超时、断网、上游报错或限流，不自动把相同问题再次发送给另一服务；页面允许用户主动重试。这样避免已完成但响应丢失的请求被重复生成。停止等待不保证服务器已经开始的生成会停止。

部署文件与逐步操作见 [Cloudflare Worker 部署说明](../workers/iching-ai/README.md) 和 [Appwrite 验证及升级说明](../appwrite/iching-probe/README.md)。静态网站仍无需构建；服务端需单独部署。Appwrite 同步请求最长 30 秒，本实现的 Gemini 调用在 23 秒超时；需先用检查页的完整解卦测试确认输出与用时，再开启公开接口。本站没有把托管平台免费额度等同于 Gemini 免费额度，各自受账号的配额与计费设置约束。

网页用于传统文化体验与个人思考。卦辞与爻辞提供阅读材料；《筮仪》本身并未给出一套完整的多爻变断语规则，网页不将自行编造的规则归于原文。

静态页面沿用此仓库现有的 GitHub Pages 发布方式；Cloudflare 与 Appwrite 函数独立部署。公开接口、跨域和限流已实测，网络地区为空时按可达性选线。
